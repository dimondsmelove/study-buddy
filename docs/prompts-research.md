# Ресёрч по промптам Study Buddy

_2026-10-05 · веб-ресёрч перед ревизией промптов (BACKLOG §5)._

Цель: не изобретать с нуля, а взять проверенные паттерны у тех, кто делает
AI-тьюторинг в проде (OpenAI, Khan Academy), и у академических работ по
мультиязычному промптингу.

## 1. Ключевые выводы

### 1.1 Промпт на языке пользователя — доказанный выигрыш, не каприз

- **XLT (Cross-Lingual-Thought)**, EMNLP 2023: шаблон «понять задачу →
  рассуждать → ответить на целевом языке» даёт **+10 п.п.** на мультиязычной
  математике (MGSM/MKQA) и сужает разрыв между языками.
  [arXiv 2305.07004](https://arxiv.org/pdf/2305.07004)
- **Beyond English** (arXiv 2502.09331): предперевод промпта в English перед
  инференсом — частая, но часто **проигрышная** практика; для генеративных
  задач нативные инструкции лучше, вывод на языке источника выгоднее.
- **Multilingual Prompting for Diversity** (EMNLP 2025): промпт на родном
  языке **снижает культурно-специфичные галлюцинации**.
  [arXiv 2505.15229](https://arxiv.org/pdf/2505.15229)

**Вывод:** текущая схема «английский промпт + приписка “Write in <lang>”» —
именно тот антипаттерн, который критикуют исследования. Интуиция про
адаптированные шаблоны подтверждена: сначала RU (школьные конвенции
«Дано → Решение → Ответ»), потом EN/DE как независимая адаптация, не калька.
Опция на будущее при отставании качества: XLT-паттерн (рассуждать на EN,
отвечать на RU) — для DeepSeek, скорее всего, не понадобится.

### 1.2 Структура системного промпта (OpenAI GPT-4.1 Prompting Guide)

Современные модели следуют инструкциям буквально. Рабочая структура:

```
# Role and Objective
# Instructions          (буллеты; подзаголовки для деталей)
# Reasoning Steps
# Output Format
# Examples
# Context
# Final instructions + "think step by step"
```

Практические правила:

- Инструкции в начале; контекст отделён делimitерами (Markdown-заголовки —
  дефолт). При конфликте инструкций модель следует той, что **ближе к концу**.
- Конкретика вместо «fluff»: не «fairly short», а «3–5 пунктов».
- **Context reliance** — явная инструкция, откуда брать ответ: «используй
  только изображение; если данных нет — скажи, чего именно не хватает»
  (наш анти-галлюцинационный кейс).
- `temperature=0` для фактических задач (Solve/Quiz/Translate);
  `max_completion_tokens` — жёсткий отсеч (у нас сейчас нет и его — дыра).
- «Делай X» надёжнее, чем «не делай Y»; при запрете формулируй альтернативу.
- Модель без явного формата склонна добавлять лишнюю прозу и форматирование —
  задавать формат + примеры.

Источники:
[GPT-4.1 Prompting Guide](https://developers.openai.com/cookbook/examples/gpt4-1_prompting_guide),
[OpenAI best practices](https://help.openai.com/en/articles/6654000-best-practices-for-prompt-engineering-with-openai-api)

### 1.3 Педагогика в промптах (Khan Academy, 7 шагов Khanmigo)

Единственные, кто публично описал промпт-процесс тьюторинг-продукта:

1. Понять идеальный паттерн «тьютор–студент» (2-sigma problem Блума).
2. Learning science: тьютор встречает студента там, где он есть, даёт
   немедленную обратную связь, провоцирует самообъяснение.
3. Персонализация из данных (курсы, язык, интересы).
4. В промпте проектируются **тон, личность и тип задаваемых вопросов**.
5. Тест на разнообразных персонах (эмодзи убрали для серьёзных тем — нашли
   на пилотах).
6. Безопасность/гардрейлы.
7. Итерация по фидбеку: жалоба «Khanmigo повторяется» → переписали промпты на
   «экономию языка» и запрет повторов вопросов.

[Блог Khan Academy](https://blog.khanacademy.org/khan-academys-7-step-approach-to-prompt-engineering-for-khanmigo)

**Что взять:** `npm run quality` + `compare` — это и есть шаги 5 и 7.
«Экономию языка» (кратко, без повторов) — явно в system prompt.

### 1.4 Сократический режим (для задачи Hint, если делать)

- Paper «Prompting LLMs With the Socratic Method» (arXiv 2303.08769, 135+
  цитирований): никогда не давать ответ; один точный наводящий вопрос за раз;
  подстройка под уровень студента.
- Промпт Khanmigo «Tutor Me» (официальный GPT от Khan Academy) — золотая жила
  правил: сначала выяснить, на каком шаге студент застрял; инкрементальные
  подсказки вместо решения; **help-abuse guard** (студент долбит «не знаю» —
  не вываливать ответ); учить на примерных задачах, не на задаче студента.
  [Полный текст](https://github.com/LouisShark/chatgpt_system_prompt/blob/main/prompts/gpts/hRCqiqVlM_Tutor_Me.md)

Ещё сократовские шаблоны:
[mustvlad/ChatGPT-System-Prompts](https://github.com/mustvlad/ChatGPT-System-Prompts/blob/main/prompts/educational/socratic-tutor.md)

### 1.5 VLM-специфика (vision-модели)

Гайд по промптингу VLM: просить модель **сначала описать видимое**, потом
отвечать (chain-of-note); явно указывать, что искать на кропе; просить назвать
нечитаемое.
[Гайд](https://www.edge-ai-vision.com/2025/03/vision-language-model-prompt-engineering-guide-for-image-and-video-understanding)

## 3. Архитектура промптов (верхний уровень)

```
src/shared/prompts/
  system.ts     — системный промпт (структура из §1.2), версия, дата
  tasks.ru.ts   — шаблоны задач на русском (эталон)
  tasks.en.ts   — независимая адаптация (не калька)
  tasks.de.ts   — позже
  index.ts      — выбор по языку ответа, подстановка <lang>
```

Слои сверху вниз:

1. **Системный** — роль; grounding («опирайся только на изображение, назови
   нечитаемое»); формат (Markdown/LaTeX); экономика языка; языковое правило.
2. **Задача** — цель + структура вывода (дефолт, неприменимые секции
   пропускаются) + ограничения (длина в пунктах/токенах).
3. **Язык** — весь шаблон на языке пользователя; auto = язык вопроса.
4. **Параметры** — temperature (0 для Solve/Quiz/Translate), max_tokens.

Прозрачность (требование пользователя): тексты промптов — данные в одном
модуле; при желании — отладочный view «что уходит модели» в настройках.

## 4. Что проверить прогоном после ревизии

- RU-промпт vs «EN + приписка» на одних фикстурах: естественность RU-ответов.
- Структура-дефолт: нет ли мусорных секций («частых ошибок нет») на простых.
- Анти-галлюцинация: фикстура с обрезанным/нечитаемым кропом → модель должна
  назвать, чего не хватает, а не выдумывать.
- temperature=0: два прогона Solve → одинаковый ответ (воспроизводимость).
- Языки: Solve на DE-кропе при auto → ответ на языке интерфейса.

# Study Buddy backend

The backend is an independently runnable Node service. Use Node **22.22.2** (the repository .nvmrc pins this version). It uses Node's built-in node:sqlite API, which is experimental in this Node release; startup prints Node's experimental API warning. No SQLite package or provider SDK is installed.

Install dependencies with npm ci, then set these runtime environment variables and run npm run backend:

- OPENROUTER_API_KEY: server-only provider credential.
- SESSION_HMAC_SECRET: at least 32 UTF-8 bytes, used to hash short-lived issuance IP buckets.
- DATABASE_PATH: SQLite file path; defaults to ./data/study-buddy.sqlite.
- HOST: bind address; defaults to 127.0.0.1.
- PORT: listen port; defaults to 8787.
- ALLOWED_ORIGINS: comma-separated exact extension origins, for example chrome-extension://extension-id. Empty means requests without an Origin header only. Only exact origins in the allowlist are echoed; unlisted origins are rejected. HTTP/HTTPS origins must be explicitly listed.
- TRUSTED_PROXY_IPS: optional comma-separated exact proxy peer IPs. Forwarded client IPs are used only when the direct socket peer is listed and the forwarding chain is valid and bounded. Leave empty when binding directly.

Keep both secrets in the backend process environment. They are not Vite defines or extension build variables. `STUDY_BUDDY_GATEWAY_URL` is the public backend origin compiled into the extension; it defaults to `http://127.0.0.1:8787` and must be an origin without a path, query, or fragment. The manifest grants only that gateway host. Provider selection, URL, model chain, prompts, and generation parameters are fixed by server code. A trusted in-process factory option is used by fake-provider tests and an operator-owned proxy; no HTTP request can set the upstream URL.

`npm run backend` builds the Node service into ignored `.backend-dist/` and starts it; `npm run backend:build` only builds. Build the extension with `STUDY_BUDDY_GATEWAY_URL=https://your-backend-origin npm run build` when it should use a remote gateway. `npm run preview:local` builds against a temporary loopback gateway and launches an isolated Chromium profile with an HTTP fake upstream. `npm run contracts:backend` runs deterministic fake-only HTTP, SQLite, image, and SSE contracts; it does not read provider credentials or make provider requests. `npm run typecheck:backend` checks backend and shared TypeScript.

Operational state contains hashed session tokens, durable anonymous installation IDs and hashed installation secrets, opaque HMAC IP buckets, request fingerprints (SHA-256), cooldowns, operation statuses, and per-installation monthly spent/reserved wallet entries with provider generation IDs for unresolved charges. Installation identities and budget ledger rows do not expire automatically; clearing local extension data does not delete server-side identity or ledger state. Expired issuance buckets and completed idempotency records are pruned at startup and on the next session issuance or generation admission; removal is lazy. It does not store message text, images, generated output, or provider response bodies. HTTP logs contain only method, route name, status, and duration. The database file is set to mode 0600; the default data directory is created as mode 0700. Keep custom database paths in a private directory.

The HTTP API bootstraps an anonymous installation and its first session at POST /api/v1/session. The response includes a durable installation ID and one-time secret; the backend stores only its SHA-256 hash, and the extension stores the credential separately from the expiring bearer. POST /api/v1/session/recover accepts that credential to issue a session for the same installation. POST /api/v1/session/claim associates a still-valid legacy bearer with a durable installation; retrying a claim keeps the subject and rotates the secret. POST /api/v1/session/renew renews a bearer, and POST /api/v1/generations streams generations. The generation stream emits context, fallback, delta, and a terminal complete or error event.

Each image is limited to 4 MiB decoded, and PNG/JPEG/WebP dimensions are bounded to 16,384 pixels per side and 40 million pixels total. The service validates headers/chunk structure without decompressing pixels. Selected text is estimated at one token per four UTF-8 bytes with a 20,000-token reserve under the nominal 200,000-token context budget; this estimate is not a provider tokenizer or exact bound.

The monthly wallet is $5 per anonymous installation per UTC calendar month. Each generation reserves $0.275, derived from the 1,050,000-token context at the provider's $0.25/M prompt limit plus 16,384 output tokens at $0.75/M completion limit ($0.274788, rounded up). Trusted final provider usage replaces the reservation; unresolved usage remains reserved and is reconciled by generation ID. The request uses OpenRouter max_price routing limits; prompts, model, and output cap are unchanged. References: [provider max price](https://openrouter.ai/docs/guides/routing/provider-selection#max-price), [usage accounting](https://openrouter.ai/docs/cookbook/administration/usage-accounting), [generation metadata](https://openrouter.ai/docs/api/api-reference/generations/get-generation).
